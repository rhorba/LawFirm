# Financial Management — Design Document

**Date:** 2026-02-28
**Phase:** 3
**Scope:** Core ledger (transaction CRUD, balance) + Invoices + Filtering + Export

---

## Decisions Made

| Decision | Choice | Rationale |
|----------|--------|-----------|
| MVP scope | Core ledger + Invoices | High business value, avoids retainer/trust/tax complexity for now |
| Transaction type model | Direction + OperationType | Clean separation of money flow direction vs. purpose |
| Invoice model | Separate `Invoice` + `InvoiceItem` entities | Enables full lifecycle tracking, partial payments, PDF generation |
| UI layout | Tab in case detail + global `/financial` page | Matches lawyer workflow: per-case context + cross-case reporting |

## 1. Database Schema (Migrations V46–V49)

### V46 — Evolve `financial_transactions`

```sql
ALTER TABLE financial_transactions
  ADD COLUMN direction VARCHAR(10) NOT NULL DEFAULT 'EXPENSE'
    CHECK (direction IN ('REVENUE', 'EXPENSE')),
  ADD COLUMN operation_type VARCHAR(20) NOT NULL DEFAULT 'OTHER'
    CHECK (operation_type IN (
      'OPENING_FEE', 'PROCEDURE_FEE', 'INTERVENTION_FEE', 'EXPERT_FEE',
      'DOCUMENT_FEE', 'NOTIFICATION_FEE', 'JUDICIAL_TAX', 'OTHER')),
  ADD COLUMN payment_mode VARCHAR(15)
    CHECK (payment_mode IN ('CHECK', 'TRANSFER', 'CASH', 'CREDIT_CARD', 'MONEY_ORDER')),
  ADD COLUMN account_number VARCHAR(50),
  ADD COLUMN deleted_at TIMESTAMP;

-- Migrate existing data
UPDATE financial_transactions SET direction =
  CASE WHEN transaction_type = 'PAYMENT' THEN 'REVENUE' ELSE 'EXPENSE' END;

ALTER TABLE financial_transactions DROP COLUMN transaction_type;

CREATE INDEX idx_transactions_direction ON financial_transactions(direction);
CREATE INDEX idx_transactions_deleted_at ON financial_transactions(deleted_at);
```

**Enum values:**

| Enum | Values |
|------|--------|
| `direction` | `REVENUE`, `EXPENSE` |
| `operation_type` | `OPENING_FEE`, `PROCEDURE_FEE`, `INTERVENTION_FEE`, `EXPERT_FEE`, `DOCUMENT_FEE`, `NOTIFICATION_FEE`, `JUDICIAL_TAX`, `OTHER` |
| `payment_mode` | `CHECK`, `TRANSFER`, `CASH`, `CREDIT_CARD`, `MONEY_ORDER` |

**Retained fields:** `amount`, `payment_date`, `payment_reference`, `account_number` (new), `lawyer_payment_year`, `fiscal_year_from`, `fiscal_year_to`, `description`, `deleted_at` (new), + BaseEntity audit cols.

### V47 — `invoices` table

```sql
CREATE TABLE invoices (
  id              BIGSERIAL PRIMARY KEY,
  case_id         BIGINT NOT NULL REFERENCES cases(id),
  invoice_number  VARCHAR(50) NOT NULL UNIQUE,
  issue_date      DATE NOT NULL,
  due_date        DATE,
  status          VARCHAR(15) NOT NULL DEFAULT 'DRAFT'
                    CHECK (status IN ('DRAFT', 'SENT', 'PAID', 'CANCELLED')),
  subtotal        DECIMAL(15,2) NOT NULL DEFAULT 0,
  tax_amount      DECIMAL(15,2) NOT NULL DEFAULT 0,
  total_amount    DECIMAL(15,2) NOT NULL DEFAULT 0,
  notes           TEXT,
  created_at      TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at      TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  version         BIGINT NOT NULL DEFAULT 0,
  deleted_at      TIMESTAMP
);

CREATE INDEX idx_invoices_case   ON invoices(case_id);
CREATE INDEX idx_invoices_status ON invoices(status);
```

**Invoice number format:** `FAC-{YYYY}-{NNNN}` (e.g. `FAC-2026-0001`), auto-generated by the service.

**Status transitions (valid only):**
```
DRAFT → SENT → PAID
DRAFT → CANCELLED
SENT  → CANCELLED
```

### Key Service Rules

**`FinancialTransactionService`:**
- Transactions are **immutable** after creation — no update endpoint, soft delete only (`deletedAt = now()`)
- Balance is computed on-the-fly via DB aggregation (`SUM WHERE direction = REVENUE` minus `SUM WHERE direction = EXPENSE`), never stored as a column
- All queries filter `WHERE deleted_at IS NULL`
- Export uses Apache POI (Excel) and iText/JasperReports (PDF)

**`InvoiceService`:**
- Auto-generates `invoice_number` as `FAC-{year}-{sequence}` using a DB sequence or `MAX(id)` fallback
- `total_amount` = `subtotal` + `tax_amount`, recalculated from line items on create
- Status transitions validated — invalid transitions throw `BadRequestException`
- PDF generated server-side (iText or Jasper template)

**`CaseMapper` update:**
- `calculateFinancialSummary()` switches from `transactionType == PAYMENT` to `direction == REVENUE`

### TanStack Angular Query Patterns

```typescript

transactions = injectQuery(() => ({
  queryKey: ['transactions', this.filters()],
  queryFn:  () => this.financialService.getTransactions(this.filters(), this.page())
}))

createMutation = injectMutation(() => ({
  mutationFn: (req) => this.financialService.createTransaction(req),
  onSuccess:  () => this.queryClient.invalidateQueries({ queryKey: ['transactions'] })

// Case financial tab

  queryKey: ['transactions', 'case', this.caseId()],
  queryFn:  () => this.financialService.getTransactionsByCase(this.caseId())
```

### UI Rules

- **Transaction form:** modal dialog (consistent with case/lawyer/client create modals)
- **Direction toggle:** selecting EXPENSE reveals `operationType` dropdown (7 options). Selecting REVENUE hides it — the full amount is the revenue entry
- **Invoice line items:** Angular `FormArray` with add/remove row buttons, `line_total` auto-calculated as `quantity × unit_price`
- **Status badges:** DRAFT=gray, SENT=blue, PAID=green, CANCELLED=red
- **Export:** Blob download triggered in-browser via `URL.createObjectURL()`
- **Soft delete confirmation:** same confirm dialog pattern used in lawyer deactivation

### TypeScript Models

```typescript
export type TransactionDirection = 'REVENUE' | 'EXPENSE';

export type OperationType =
  'OPENING_FEE' | 'PROCEDURE_FEE' | 'INTERVENTION_FEE' | 'EXPERT_FEE' |
  'DOCUMENT_FEE' | 'NOTIFICATION_FEE' | 'JUDICIAL_TAX' | 'OTHER';

export interface TransactionResponse {

  direction: TransactionDirection;
  operationType: OperationType;
  paymentMode?: PaymentMode;
  amount: number;
  paymentDate?: string;
  paymentReference?: string;
  accountNumber?: string;
  description?: string;
  createdAt: string;
  createdBy: string;
}

export interface FinancialSummary {
  totalRevenue: number;
  totalExpenses: number;
  balance: number;
  transactionCount: number;
}

export interface InvoiceResponse {
  id: number;
  caseId: number;
  invoiceNumber: string;
  issueDate: string;
  dueDate?: string;
  status: InvoiceStatus;
  subtotal: number;
  taxAmount: number;
  totalAmount: number;
  notes?: string;
  items: InvoiceItemResponse[];
  createdAt: string;
}
```

## Out of Scope (Phase 4+)

- Retainer management (deposits, draw-downs)
- Trust account management (special permissions)
- Fee agreements (hourly, flat fee, contingency)
- Payment plans
- Payment reminders / overdue tracking
- Tax reporting preparation
- Expense approval workflow
